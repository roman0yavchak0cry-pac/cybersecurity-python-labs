# Лабораторна робота №3 — варіант 5

**Тема:** Прикладні бібліотеки Python для побудови вебзастосунків.
**Предметна область:** облік спрацювань засобів захисту.

## Предметна область і модель даних

API обліковує кількість спрацювань засобів захисту за навчальні інтервали.
Категорії: `firewall`, `ids`, `antivirus`; одиниця `value` — **events**
(невід’ємне ціле число); поріг для аналізу — **15**. Поріг не є верхньою
межею допустимих значень. `status`: `new`, `in_progress`, `done`.
Дані навчальні, а не реальні події інфраструктури.

Таблиця `categories`: `id` — первинний ключ; `name` — непорожнє унікальне ім’я.
Таблиця `records`: `id` — первинний ключ; `code` — унікальний код;
`title` — назва спрацювання; `category_id` — зовнішній ключ до `categories.id`;
`value` — кількість; `status` — стан опрацювання. Зв’язок 1:N.
`ON DELETE RESTRICT` забороняє видалення категорії, що має записи.
Точна схема та всі обмеження містяться у **`schema.sql`**, без ORM.

## Відтворення (виконувати з кореня репозиторію)

Python 3.10 або новіший; активувати наявне `.venv`.

```powershell
python -m pip install -r requirements.txt
python -m labs.lab03.database
python -m labs.lab03.seed
python -m labs.lab03.seed
uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
```

Перший запуск `seed` додає **3 категорії, 8 записів**, другий не змінює
даних. Відкрийте `http://127.0.0.1:8000/docs` (Swagger UI) та
`http://127.0.0.1:8000/openapi.json` (OpenAPI).
Перед цим у кореневому `requirements.txt` мають бути зафіксовані версії
`fastapi`, `uvicorn`, `pydantic`, `ruff`; не видаляйте залежності ЛР №1–2.

## Обов’язкові маршрути

| Метод | Маршрут | Очікуваний результат |
|---|---|---|
| GET | `/ping` | 200, `{"status":"ok"}` |
| GET | `/student` | 200, `student_name`, `group_name`, `variant_number` |
| GET | `/categories` | 200, список за `id` |
| POST | `/categories` | 201, нова категорія |
| DELETE | `/categories/{category_id}` | 204, лише порожня категорія |
| GET | `/records` | 200, список із фільтрами і JOIN |
| GET | `/records/{record_id}` | 200, один запис |
| POST | `/records` | 201, новий запис |
| PUT | `/records/{record_id}` | 200, повна заміна 5 полів |
| DELETE | `/records/{record_id}` | 204, без тіла |
| POST | `/records/bulk` | 201, 1–100 записів в одній транзакції |

Для `GET /records`: `category_id > 0`, `status`, `min_value >= 0`
(ціле число), `q` (буквальний підрядок у `title`, чутливий до регістру,
1–120 символів), `limit` (1–100, типово 20), `offset >= 0` (типово 0).
Фільтри об’єднуються через `AND`, результати відсортовані за `id`.
Помилки: `404` — немає ресурсу, `409` — конфлікт унікальності або
видалення непорожньої категорії, `422` — невалідний запит,
`500` — неочікувана помилка бази.

## Приклади основних запитів у Swagger

`GET /categories` → `firewall`, `ids`, `antivirus`.
`GET /records` → коди `V05-01` … `V05-08`.
`GET /records?category_id=1&status=new&limit=5&offset=0` → `V05-01`, `V05-04`.
`GET /records?min_value=15` → значення не менше 15.

`POST /records`, **Request body**:

```json
{"code":"V05-TEST","title":"Тестове спрацювання firewall","category_id":1,"value":20,"status":"new"}
```

Очікувано: **201**, додаткові поля `id` і `category_name: "firewall"`.
Запам’ятайте отриманий `id`; далі `GET /records/{id}`, `PUT /records/{id}`
(всі п’ять полів), `DELETE /records/{id}` → відповідно **200, 200, 204**.

`POST /records/bulk`, коректний пакет:

```json
[
  {"code":"V05-BULK-01","title":"Новий запис пакета 1","category_id":1,"value":5,"status":"new"},
  {"code":"V05-BULK-02","title":"Новий запис пакета 2","category_id":2,"value":25,"status":"done"}
]
```

Очікувано: **201**, збережені обидва записи.

Перевірка відкату дубліката (перший код має залишитися відсутнім):

```json
[
  {"code":"V05-ROLLBACK-409","title":"Перший новий запис","category_id":1,"value":4,"status":"new"},
  {"code":"V05-01","title":"Дублікат існуючого коду","category_id":2,"value":5,"status":"new"}
]
```

Очікувано: **409**, кількість записів не змінилася,
`GET /records?q=Перший новий запис` не повертає `V05-ROLLBACK-409`.

Перевірка відкату неіснуючої категорії:

```json
[
  {"code":"V05-ROLLBACK-404","title":"Перший відкатний запис","category_id":1,"value":4,"status":"new"},
  {"code":"V05-UNKNOWN-CAT","title":"Невідома категорія","category_id":999999,"value":5,"status":"new"}
]
```

Очікувано: **404**, жоден із двох записів не збережений.

## Обов’язкові 14 перевірок (за методичкою, завдання 3)

Фіксуйте *фактичні* HTTP-коди, відповіді/стан бази та скриншоти для звіту.

1. Перша і повторна `seed.py`: 3 категорії, 8 записів, без дублікатів.
2. `GET /ping`, `/student`, `/categories`: **200**, коректні дані.
3. CRUD окремого запису: **201 → 200 → 200 → 204**.
4. Фільтрація (один і два фільтри), `limit`, `offset`, порядок `id`.
5. `value=-1`, `title="   "`, `status="invalid"`, `limit=0`: **422**, база незмінна.
6. Для варіанта 5 `value=1.5` (неціле): **422**.
7. Неіснуючі `record_id` і `category_id` під час створення: **404**.
8. Повторні `code` і назва категорії: **409**, наявні записи не змінені.
9. Видалення непорожньої категорії: **409**; створити порожню категорію,
   видалити її: **204**.
10. Коректний пакет із двох нових записів: **201**, збереглися обидва.
11. Пакет: новий + уже наявний `code`: **409**, новий не збережено.
12. Пакет: новий + `category_id=999999`: **404**, новий не збережено.
13. `GET /records?q=' OR 1=1 --`: рядок є даними, записи не змінюються.
14. Створити запис, зупинити сервер `Ctrl+C`, запустити знову,
    отримати запис за `id`: **200**; SQLite зберіг його на диску.

Для тесту порожньої категорії `POST /categories`:
`{"name":"training_empty"}`, потім видаліть її за новим ID.
Для 14-го тесту використайте унікальний код `V05-PERSIST`.
Для перевірок 11–12 порівняйте кількість записів **до** і **після**;
за потреби використайте `limit=100` і `offset`.
